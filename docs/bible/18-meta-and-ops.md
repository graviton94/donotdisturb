# 18 · 메타 시스템 · 운영 기반

## 1. 일일 도전 (Lv11)

| 항목 | 내용 |
|---|---|
| 형식 | 고정 시드 판 60초 기록전. 모두 같은 판·같은 덱(그날 지정 6종)으로 점수 경쟁 |
| 입장 | 하루 열쇠 2개 (Lv52부터 3개). 광고·결제로 늘리지 않는다 |
| 점수 | 60초 동안 번 P (회차 배율 무관, 도전 전용 고정 배율) |
| 보상 | 일일 도전 참가 조각 1, 개인 최고 갱신 조각 2. 주간 순위는 1위·2~10위·11~100위·나머지 유효 참가자에게 조각 8·5·3·1개를 주당 한 번 지급. |
| 꾸미기 조각 | 10개 = 무료 라인 꾸미기 1개 교환 |
| 엔진 | **반영(11-23)** `Meta.challengeBoard/startChallenge/finishChallenge`: 날짜 시드 + 3~8티어에서 고른 6종 덱(강화 30·Lv40·배터리 60 고정, 계정 보너스 없음), 열쇠 2개(Lv52부터 3개), 최고 기록 갱신 조각 2·참가 1. 로그인한 계정의 주간 순위는 Firestore에 표시한다. 주간 지급은 검증된 서버 정산 연결 후 시작한다. |

## 2. 업적 · 칭호

| 분류 | 예 (조건 → 칭호) |
|---|---|
| 진행 | 첫 초기화 → "초기화 입문", 첫 동기화 → "클라우드 이민자", 마지막 앱 → "알림 없는 사람" |
| 판 | 10연쇄 → "연쇄 반응", 과부하 파동 9단 → "알림 해일" |
| 수집 | 한 티어 6종 모두 보유 → "<권역> 컬렉터", 프로 버전 60종 → "프로 정리왕" |
| 덱 | 시너지 상한 ×4 달성 → "풀 시너지" |
| 돌발 | 스팸 1,000개 치움 → "스팸 사냥꾼", 앱 충돌 100회 재시작 → "재부팅 장인" |
| 일일 도전 | 30일 연속 참가 → "출석왕" |

칭호는 패널·기록 화면에 하나 표시. 보상은 꾸미기 조각만(진행 보상 없음).

**엔진 반영 (11-23)**: `core/.../Meta.kt`. 업적 9종(초기화 입문·클라우드 이민자·알림 없는 사람·연쇄 반응·알림 해일·스팸 사냥꾼·재부팅 장인·프로 정리왕(프로 10종)·알림 개근왕(30일 개근)) → 칭호 + 꾸미기 조각 1~3. 평생 통계 카운터(`Stat`)는 계정에 저장. **일일 미션**: 6종 풀(터뜨리기 30·밀기 150·5연쇄·스팸 10·강화 20·과부하 파동 3)에서 날마다 다른 3개, 세 개를 다 하면 데이터 35(17장). 게임은 스와이프마다 `Meta.record`, 초기화·동기화는 `Meta.reset/sync`를 부른다.

누적 앱 도감은 보유 10·20·30·40·50·60종에 조각을 한 번씩 지급한다. 확장 카탈로그 66종은 조각·데이터·★ 선택권을 지급한다. 코어 지급 계약과 서버 신뢰 범위는 [v1.6 화면 계약](../balance/api-changes.md#v16-도감주간-지급기간-한정-콘텐츠)을 따른다.

## 4. 운영 기반

| 영역 | 설계 |
|---|---|
| 저장 | `GameState` 전체를 거래 단위로 저장(DataStore, 스와이프·구매·초기화마다). 코덱은 `core/.../Save.kt`(JSON, 큰 수는 10진 문자열, 모르는 키 무시·빠진 키 기본값, 테스트로 왕복 검증). 저장 실패 시 직전 저장 유지. 규칙 버전(`rulesVersion`)과 콘텐츠 팩 목록을 함께 저장 |
| 복원 | Android Auto Backup + 수동 백업 코드(내보내기 문자열). 기기 이동 시 오프라인 정산은 한 번만 |
| 시간 조작 방어 | 오프라인 정산은 같은 부팅 안에서는 단조 시계(elapsedRealtime) 기준. 부팅이 바뀌면 벽시계 차이를 상한(8~12시간)으로 자른다. 미래 시각 → 정산 0 |
| 결제·광고 지급 | `claim_id` 멱등 지급, 지급 기록을 저장과 같은 거래에 기록, 재시작 후 미지급 재확인 |
| 원격 규칙 | 키별 범위를 적용하는 [원격 조정 계약](../balance/remote-tuning.md). 기간 한정 팩은 UTC 창으로 활성화한다. |
| 텔레메트리 | 이벤트: `ftue_*`(16장), `level_up`, `reset(files, level)`, `sync(gb)`, `app_buy(id)`, `deck_set(sets, cap_hit)`, `offline_claim(p, doubled)`, `ad_offer/ad_complete(placement)`, `iap_purchase(sku)`, `session_start/end`. 개인정보 없음, 기기 ID는 앱 범위 ID |
| 성능 | 판 계산은 `core/` 순수 Kotlin(테스트 45개). BigInteger는 표시 직전에만 문자열로 |
| 접근성 | 텍스트 확대, 색만으로 구분 금지(스팸=빨강 + 아이콘), 움직임 줄이기에서 셰이크 0(디자인 토큰) |


### 규칙 B 검증에서 확인한 지급 경계

저장 외피는 버전 1이다. 광고 지면의 사용 기록은 UTC 날짜에 맞춰 갱신하고 최근 7일의 영수증을 보존한다. 결제 영수증은 계정에 계속 남긴다. 복귀 광고의 제안은 코어 세션이 당일의 양수 정산 한 건에 한해 사용하고 플랫폼은 SDK가 보상을 확인했을 때 지급 ID를 전달한다. [화면 계약](../balance/api-changes.md)
