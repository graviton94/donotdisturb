## 2. 첫 15분 공백 (화면 세션 측정)

## 3. 앱 도감 수집 보상 (새 콘텐츠, 화면이 UI 준비됨)
화면에 앱 도감(보유/구매 가능/실루엣, 수집률)이 들어갔다. 보상은 네가 설계하고 코어에 넣어라.
- 보유 앱 수 마일스톤(예: 10/20/30/40/50/60)별 보상: 데이터·꾸미기 조각·프리미엄 선택권 등.
- 수치는 BM 역전 0, 광고 가속 ≥1.25배를 지키는 범위에서 정해라.
- **WebSession 추가만**:
  - `panel().book = { owned, total, milestones: [{ at, reward, claimed }] }`
  - `claimBook(at)` — 1회만 지급
- 계약을 `docs/balance/api-changes.md`에 적어라. 화면 세션이 도감 시트에 받기 버튼을 붙인다.

## 4. 주간 순위 보상 (설계 + 코어 지급 경로)
일일 도전 주간 순위가 들어갔다(같은 판, 주마다 전체 순위, 로그인 플레이어만).
- 순위 구간별 보상을 설계해라(예: 1위, 상위 10, 상위 100, 참가). 꾸미기 조각 중심으로, 과금 가치를 넘지 않게.
- 코어에 `grantWeekly(claimId, tier)`를 추가해라. claim id 1회 지급.
- 서버 정산(주 마감 때 순위 계산, 지급 표시)은 화면·플랫폼 세션이 Functions로 만든다. 너는 구간 정의와 수치만 준다.

## 5. 역할 확장 — 라이브 운영·경제 텔레메트리 담당
출시 뒤 숫자를 지키는 일을 네가 맡는다. 이번 판에는 기반을 만든다.

### 5-1. 원격 조정 손잡이 (Remote Config)
- 앱 업데이트 없이 바꿀 수 있는 **안전한 손잡이 목록과 허용 범위**를 정해라. 예: 오프라인 효율, 스팸 보충 확률, 카드 가격 배수, 이벤트 주기.
- 코어에 `WebSession.applyTuning(json)`을 추가해라(추가만). 범위 밖 값은 무시하고 기본값을 쓴다. 저장에는 넣지 않는다.
- Firebase Remote Config 연동(가져오기 → 브리지 → `applyTuning`)은 화면 세션이 한다. 키 이름·타입·기본값·범위를 `docs/balance/remote-tuning.md`에 적어라.
- 각 손잡이를 한계까지 돌렸을 때 v1.5 지표가 어디까지 움직이는지 표로 보고해라. 운영자가 어디까지 돌려도 안전한지 알 수 있어야 한다.

### 5-2. 라이브 KPI 정의
- 앱이 보내는 분석 이벤트를 기준으로 지표 정의서를 써라(`docs/balance/live-kpi.md`). 이벤트는 `track()`이 보내는 `ftue_step`, `purchase`, `ad_show`/`ad_reward`, `login`, `ad_fail` 등이다.
  - D1/D7/D30 잔존, 첫 가이드 퍼널, 첫 구매 전환, 광고 시청률, 세션 길이와 하루 세션 수
  - 각 지표의 시뮬 예측값과 경보 임계값
- 지금 이벤트로 측정할 수 없는 지표가 있으면, 화면 세션이 추가할 이벤트 이름과 파라미터를 목록으로 달라(예: `level_up{level}`, `reset{files}`, `chain{k,end}`).

### 5-3. 한정 이벤트 2종 설계
- 콘텐츠 팩 구조(`docs/bible/14-live-updates.md`)로 돌릴 수 있는 **기간 한정 이벤트 2개**를 설계하고 코어에 넣어라. 예: 주말 2배 연쇄 주간, 특정 권역 앱 시너지 주간.
- 시뮬로 영향을 재라: 해당 주 진행 가속, 끝난 뒤 반동, BM 역전 0.
- 화면 쪽 표시(배너·남은 시간)는 계약만 주면 화면 세션이 만든다.
